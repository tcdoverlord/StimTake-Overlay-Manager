StimTake deck-switch initialization fix candidate
=================================================

Change scope
- Only the deck-switch UI synchronization sequence was changed.
- Deck switching now awaits the selected deck's slot-map POST before allowing
  another Click-to-Run Mode toggle or another deck selection.
- After successful sync, it reconciles backend state and refreshes the visible
  cards without changing Click-to-Run Mode's ON/OFF setting.
- No queue, Stop, overlay URL, or memory-pressure runtime rules were changed.

Build
1. Extract this package on Windows.
2. Run BUILD-WINDOWS-RELEASE.cmd.
3. The rebuilt executable/installer should be generated by that script.

Required test
- Start StimTake and confirm the deck's cards appear on initial launch.
- With Click-to-Run Mode ON, switch across Halloween and another built-in deck.
- Repeat with Click-to-Run Mode OFF.
- Confirm cards refresh without toggling Click-to-Run Mode.
- Test assigned overlays and their OBS URLs, activation, Stop, queue, and deck
  switching. This source change has not been validated in a live OBS session.

The included pre-existing EXE and installer are retained for reference only;
they do not contain this new UI source change until rebuilt on Windows.
